# Shared provider protection — 24 October 2026

## What changed

Provider cooldowns can now survive Vercel instance changes. Each model has an atomic MongoDB lease before generation. A reservation lasts at most 45 seconds after an abandoned request; normal completion releases it with four seconds of spacing. The lease outlasts the complete 35-second request deadline. Daily exhaustion blocks that key/model until the next Pacific midnight, including daylight-saving changes. Minute limits respect the provider retry interval. Other models and saved-source answers remain available.

This does not add provider allowance or make free-tier availability permanent. Google quotas apply to the API project, not separately to every key. A separate optional Redis gate controls application request traffic; the MongoDB feature only coordinates provider calls and cooldowns.

## Private configuration

Set server-only `QUOTA_MONGO_URI` and `QUOTA_DB_NAME` in the deployment environment. The portfolio deployment uses the existing, owner-approved `shape_up_demo` database and a separate `provider_quota` collection. A new installation should use its own least-privilege account and a dedicated `commecs_demo` database. Never include credentials in browser variables, source, screenshots, or archives. Redeploy after changing production values.

Documents contain only a hashed key/model identifier, lease token, expiry times and cooldown reason. They do not contain messages, answers, raw keys, or IP addresses. There is at most one state document per configured key/model. The connection pool is capped at two; connection and operation waits are bounded to five seconds to allow Atlas DNS/TLS cold starts.

With no URI, protection remains per process. With configured but unavailable shared storage, live generation fails closed and the existing sourced fallback handles the question. Public readiness at `/api/health?check=quota` returns only `ready`, `unavailable`, or `not-configured`; it never returns a URI or exception details. The ordinary health check reports configuration mode without claiming a successful database connection.

## Validation

`npm run verify` checks server/quality types, the complete automated suite and production client/server builds. Shared-quota regressions cover concurrent callers, persisted daily exhaustion, provider retry delays, abandoned requests and Pacific daylight-saving reset dates. These tests use isolated in-memory state and do not spend provider quota. Run the opt-in readiness check after deployment, then one bounded real chat smoke test; automated tests alone do not prove external availability.

The toolchain now uses Node 24, Vite 8, Vitest 5 and MongoDB driver 7.7.0. The lockfile is included for reproducible installs.
